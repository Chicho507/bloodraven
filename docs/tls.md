# HTTPS privado con validación DNS

El perfil opcional usa Caddy y su módulo Cloudflare para obtener y renovar un certificado de Let's Encrypt mediante DNS-01. Cloudflare actúa como proveedor DNS: no es un túnel ni un proxy del tráfico del portal. No se instala un certificado Cloudflare Origin CA, que no es de confianza para los navegadores que acceden directamente.

Se necesita un dominio autorizado cuya zona DNS pública esté gestionada por Cloudflare. El token debe tener `Zone:DNS:Edit` y `Zone:Zone:Read` únicamente sobre esa zona. La cuenta no necesita una clave API global. El asistente guarda el token en `secrets/cloudflare_api_token`, con permisos 0600 y directorio 0700. Solo el proxy lo monta; no se añade a `.env`, a la imagen Docker ni al repositorio. Los administradores del host o de Docker pueden leerlo; un secreto de Compose no protege frente al administrador del servidor.

1. Crear el registro del nombre del portal en los DNS corporativos. El mismo nombre puede resolver a la IP interna desde LAN y a la IP de NAT desde VPN. La VPN debe entregar el DNS adecuado y las rutas necesarias. No hace falta publicar registros A/AAAA del portal ni habilitar la nube naranja en Cloudflare para DNS-01. Si hay una zona interna con el mismo nombre, la validación DNS debe consultar resolutores que vean la zona pública.
2. Mantener el firewall autorizado solo para LAN/VPN y el NAT de TCP 443 hacia la IP interna. HTTPS no configura estas reglas. El perfil sustituye la publicación en todas las interfaces por una publicación en la IPv4 privada indicada, sin publicar el backend, HTTP ni HTTP/3 UDP.
3. Permitir la salida necesaria desde el proxy a Cloudflare y Let's Encrypt por HTTPS y la resolución DNS pública. Los resolutores de validación predeterminados son `1.1.1.1:53 1.0.0.1:53`; `BR_ACME_RESOLVERS` admite los resolutores autorizados que vean los TXT públicos. Revisar los registros CAA existentes si restringen la emisión; no modificarlos automáticamente.
4. En Linux, ejecutar `python3 scripts/configure_tls.py --hostname NOMBRE_DNS --bind-ip IPV4_INTERNA`. Pegar el token únicamente en la entrada oculta de la terminal del servidor. Se conserva el resto de `.env` y se crea un respaldo privado antes de cambiarlo. No mostrar el token en comandos, capturas o logs. Para sustituirlo, usar `--replace-token`.
5. El asistente fija `COMPOSE_FILE=compose.yaml:compose.cloudflare.yaml` en `.env`, por lo que las actualizaciones habituales siguen usando el perfil TLS. Requiere Compose 2.24.4 o posterior. Mantener el nombre de proyecto usado por el despliegue.
6. Ejecutar `docker compose -p NOMBRE_DEL_PROYECTO config --quiet`, después `docker compose -p NOMBRE_DEL_PROYECTO build app proxy` y finalmente `docker compose -p NOMBRE_DEL_PROYECTO up -d --wait --wait-timeout 180 app proxy`. No detener el proxy existente antes de terminar la construcción. El arranque del contenedor no garantiza que la emisión ya haya terminado.
7. Verificar `curl https://NOMBRE_DNS/healthz` desde un cliente LAN y otro VPN, sin `-k`, y probar el login. Ambas pruebas necesitan resolver el mismo nombre. Si falla TLS, revisar DNS, CAA, permisos del token, salida de red y los logs del proxy localmente.

Los TXT `_acme-challenge` son temporales y públicos. Los certificados públicos también registran el nombre del subdominio en Certificate Transparency: la aplicación puede ser privada aunque su nombre no sea secreto. Si es obligatorio ocultar el nombre, utilizar una CA corporativa privada.

Conservar los volúmenes de Caddy para renovaciones y evitar nuevas emisiones innecesarias. El perfil desactiva la API administrativa y el autoguardado de configuración; la clave del certificado continúa persistiendo en el volumen protegido. Una rotación o caducidad del token puede impedir renovar: comprobar periódicamente el vencimiento y la salud HTTPS.

Para volver al perfil de CA interna, restaurar el respaldo de `.env` anterior a este cambio y ejecutar Compose con `-f compose.yaml` explícitamente. Conservar todos los volúmenes. El navegador necesitará confiar nuevamente en la CA interna.

Referencias: [Caddy DNS-01](https://caddyserver.com/docs/automatic-https#dns-challenge), [módulo Cloudflare y permisos](https://github.com/caddy-dns/cloudflare), [secretos de Compose](https://docs.docker.com/compose/how-tos/use-secrets/), [Certificate Transparency](https://letsencrypt.org/docs/ct-logs/).
